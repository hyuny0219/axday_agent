# 안건 ② — 익명이면 말할 수 있을까 (사내 게시판 익명제)

버전 1.0 · 2026-09-23 · 구현 기준: `src/content/scenarios/anonBoard.ts`, `server/scenario-data.ts`

모든 자료·대사·의결 규칙은 체험용 가상 설정이며 실제 삼성화재 자료나 정책이 아니다. 고정 반응·표결 우선순위·대표 경로의 득표수는 scripted 데모용 테스트 데이터이며 live 에이전트의 정답이 아니다. live에서는 같은 최종안과 실제 논의로 각 임원이 스스로 판단한다.

## 브리핑

- 사건: **사건 02 · 익명 게시판을 열어 달라는 요구가 쌓였지만, 운영 기준이 없다**
- 결정 질문: **사내 게시판을 익명제로 바꿀까요?**
- 현재 상황: 익명 게시판을 열어 달라는 요구가 반복되지만, 운영 기준은 아직 정해져 있지 않습니다.
- 제안: 사내 게시판을 익명제로 전환한다.
- 아직 정하지 않은 것: 작성자 추적 범위 · 게시 전 검수 · 임원 열람 범위
- 특별 이사님이 할 일: 의견을 내고, 필요한 조건도 직접 제안할 수 있습니다. 마지막에는 한 표를 던집니다.
- 원안 `anon-board-original`: 사내 게시판을 익명제로 전환한다. 작성자 추적 범위, 게시 전 검수, 임원 열람 범위는 미정이다.

## 추천 문구와 조건

| 문구 | 내용 | 연결 조건 |
| --- | --- | --- |
| P1 | 한 게시판에서 먼저 시범 운영합시다. | PILOT |
| P2 | 게시 전 검수 절차를 두고 시작합시다. | SCREEN |
| P3 | 문제가 생기면 작성자를 확인할 수 있게 해 둡시다. | TRACE |
| P4 | 운영 효과를 측정한 뒤 전사로 넓힙시다. | MEASURE |
| P5 | 작성자를 누구도 추적할 수 없는 완전 익명으로 합시다. | ANON_FULL |
| P6 | 아직 확인할 것이 많습니다. 운영 기준을 더 정리해 주십시오. | (조건 없음, 요청형) |

| 조건 ID | 라벨 |
| --- | --- |
| PILOT | 한 게시판에서 시범 |
| SCREEN | 게시 전 검수 |
| TRACE | 문제 발생 시 추적 가능 |
| MEASURE | 운영 효과 측정 후 확대 |
| ANON_FULL | 완전 익명 — 추적 불가 |

**상충 조건쌍: `TRACE` ↔ `ANON_FULL`.** 둘을 함께 확정할 수 없다. 이 안건의 핵심 갈등이며, 어느 쪽도 정답이 아니다.

`TRACE`의 키워드는 긍정형(`추적 가능`·`작성자를 확인`·`확인할 수 있게`)으로 좁혔다. `추적` 한 단어만 두면 "추적할 수 없는 완전 익명"(ANON_FULL) 문장에도 걸려 상충하는 두 조건이 동시에 제안된다. `신고가 들어온`도 키워드로 쓰지 않는다 — 후속 빠른 답 "신고가 들어온 뒤에 처리해도 충분합니다."(조건 없음)는 선택 즉시 초안이 되어 키워드 추출을 거치므로, 그 표현이 키워드면 조건 없는 답에서 TRACE가 몰래 확정된다(PR #10 Codex 5차 검토). 후속 빠른 답 세 문구는 각각 `proposeConditionId`와 정확히 같은 조건만 추출돼야 한다(테스트로 고정).

키워드 추출의 부정 판정은 키워드 뒤 같은 절 안의 `없이·생략·말고`에 더해 `-지 않-`·`없-`·`안 -`·`못 하-`·`반대`를 본다 — 후속 직접 답변 "작성자를 확인하지 않겠습니다."가 `작성자를 확인`에 걸려 참가자가 거부한 TRACE가 자동 승인되던 문제(PR #10 Codex 12차 검토). 그래서 `ANON_FULL`의 키워드 `누구도 확인`은 늘 뒤따르는 "할 수 없는"에 자기 부정되지 않도록 `누구도 확인할 수 없`·`누구도 확인 못`으로 둔다(`src/domain/conditions.ts`).

## 후속 질문

CFO: **"글이 늘면 신고 처리는 누가 맡습니까? 지금은 지정된 담당자가 없습니다."**(E3)

| 선택지 | 제안 조건 |
| --- | --- |
| 게시 전 검수 절차를 두고 담당자를 지정합시다. | SCREEN |
| 신고가 들어온 뒤에 처리해도 충분합니다. | (없음) |
| 앞서 전달한 의견을 유지하겠습니다. | (유지) |

후속 질문은 앞 단계에서 확정한 조건이 아니라 아직 다루지 않은 쟁점을 끌어낸다.

## 표결 우선순위 (scripted 전용)

위에서부터 먼저 일치하는 행을 적용한다.

| 임원 | 조건 | 표 | 판단 이유 한 줄 |
| --- | --- | --- | --- |
| CEO | ANON_FULL | HOLD | 완전 익명 — 추적 불가 조건이 있어 보류 |
| CEO | (그 외) | YES | 솔직한 목소리를 여는 방향에 찬성 |
| CFO | ANON_FULL | NO | 완전 익명 — 추적 불가 조건이 있어 신고 처리 부담을 가늠할 수 없어 반대 |
| CFO | PILOT + MEASURE | YES | 한 게시판에서 시범과 운영 효과 측정 후 확대 조건이 있어 찬성 |
| CFO | (그 외) | HOLD | 한 게시판에서 시범과 운영 효과 측정 후 확대 조건이 함께 있지 않아 보류 |
| CAIO | ANON_FULL | NO | 완전 익명 — 추적 불가 조건이 있어 중복 계정·악용을 막을 수단이 없어 반대 |
| CAIO | SCREEN | YES | 게시 전 검수 조건이 있어 찬성 |
| CAIO | (그 외) | NO | 게시 전 검수 조건이 없어 반대 |
| CISO | ANON_FULL | NO | 완전 익명 — 추적 불가 조건이 있어 문제 발생 시 대응할 방법이 없어 반대 |
| CISO | TRACE + SCREEN | YES | 문제 발생 시 추적 가능과 게시 전 검수 조건이 있어 찬성 |
| CISO | TRACE | HOLD | 문제 발생 시 추적 가능 조건은 있으나 게시 전 검수 조건이 없어 보류 |
| CISO | (그 외) | NO | 문제 발생 시 추적 가능 조건이 없어 반대 |

판단 이유는 조건 라벨을 그대로 인용하며 새 수치·확정 사실을 만들지 않는다(v1.0 9절).
