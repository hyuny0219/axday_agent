# 안건 ② — 보고 준비에 쓰는 시간을 되찾아라

> **v0.8 적용:** [임원 에이전트 명세](AGENT_BOARDROOM_SPEC.md)를 먼저 적용한다. 이 파일의 자료·추천 문구·조건 확인·원안 정규화는 live/scripted 공통이다. 고정 반응·표결 우선순위·대표 경로의 득표수는 scripted 테스트 데이터이며 live 에이전트의 정답이나 강제 표가 아니다. live는 동일 최종안과 실제 논의로 각 임원이 판단한다.

> **v0.9 적용:** 브리핑에 의장 브리핑 3문장·자료별 해석·핵심 쟁점 3개를 추가하고 후속 질문을 CIO 발화로 귀속했다([판정표](REVISION_DECISIONS_v0.9.md)). 표결 규칙·조건 ID는 그대로다.

본 문서의 수치·대사·의결 규칙은 프로토타입 구현을 위한 가상 설정이며 실제 삼성화재 자료가 아니다. 조건 ID와 규칙은 개발 기본값이며 현장 리허설 후 콘텐츠로 조정 가능하다.

## 브리핑

원안 `work-assistant-original`: 여러 부서 자료를 연결해 주간 보고서를 자동 작성·공유하는 AI 업무 비서를 도입한다. 사용자별 권한, 검토 담당자, 확대 기준은 미정이다.

의장 브리핑(v0.9, `chairBriefing`):

- 상황: “주간 보고마다 부서 자료를 손으로 모으고 있습니다. 보고 준비에 쓰던 시간을 판단과 실행에 돌려줄 수 있을까요?”
- 결정 질문: “이 일을 AI 업무 비서에 맡길지 정합니다. 도입할까요? 한다면 어떤 조건을 붙일까요?”
- 내 역할: “특별 이사님은 조건을 붙여 의견을 내시고, 마지막에 한 표를 던지시면 됩니다.”

| ID | 자료 카드 | 가상 내용 | 이 자료가 말하는 것(v0.9 `insight`) | 관련 임원 |
| --- | --- | --- | --- | --- |
| E1 | 실적표 | 기준일 2026-08-31, 처리 건수 120건. 담당자 검토 완료. | 검토 완료 수치 120건(8/31 기준). | CIO |
| E2 | 업무 메일 | 기준일 2026-09-01, 처리 건수 126건. 잠정 집계, 검토 전. | 잠정 수치 126건(9/1 기준, 검토 전). E1과 다르며 어느 쪽이 최종인지는 이 자료만으로 알 수 없다. | CIO |
| E3 | 회의록 | 주간 보고마다 자료 취합을 반복한다. 다음 회의 전 보고 초안 검토 담당자를 지정해야 한다. | 취합이 매주 반복된다. 자동화 효과의 근거이자, 검토 담당자가 아직 없다는 뜻이다. | CEO · CFO·CAIO |
| E4 | 권한·운영 메모 | 부서 자료별 조회 권한이 다르다. 권한 확인, 공유 대상, 담당자 검토 절차는 아직 설계 중이다. | 권한·공유 범위가 아직 설계 중이다. 도입 전 확인이 필요하다. | CISO |

핵심 쟁점 3개(v0.9 `briefingIssues`, 기존 정리 카드 문장을 나눈 것): ① 숫자가 자료마다 다릅니다(E1·E2). ② 초안을 검토할 담당자가 없습니다(E3). ③ 권한과 공유 범위가 정해지지 않았습니다(E4). 브리핑 하단에 붙일 수 있는 조건 4개(`previewConditionIds` = PILOT·REVIEW·ACCESS·MEASURE. 위험 대안 OPEN_ALL은 조건 목록에는 있으나 미리보기에서 제외)를 읽기 전용으로 미리 보여 준다: “아래 네 가지를 조건으로 붙이면 임원들의 판단이 달라집니다.”

BRIEFING 자동 AI 정리 카드(상시 표시, ‘체험용 사전 구성’): “120건과 126건은 기준일과 검토 상태가 다릅니다. 동일 기준으로 확인이 필요하며, 어느 값이 최종 확정 수치인지는 현재 자료만으로 판단할 수 없습니다.” 차이의 원인이나 시간 절감률을 만들어내지 않는다. E1·E2를 위 문장에 연결하고, “회의 전 초안 검토 담당자 지정이 필요합니다(E3). 조회 권한과 공유 범위는 아직 설계 중입니다(E4)”를 함께 표시한다.

## 초기 임원 의견

토론 화면에는 표 아이콘·득표수 없이 검토 의견으로 표시한다.

| 인물 | 기본 발언 | 근거 |
| --- | --- | --- |
| CEO | 보고 준비를 줄이고 판단과 실행에 시간을 씁시다. | E3 |
| CFO · CAIO | 작은 범위에서 준비시간과 수정량을 먼저 확인합시다. | E3 |
| CIO | 출처·기준일을 표시하고 담당자가 확인해야 합니다. | E1, E2 |
| CISO | 접근 권한과 공유 범위를 먼저 명확히 해야 합니다. | E4 |

## 추천 문구와 구조화 조건

| 문구 ID | 참가자에게 보이는 문장 | 조건 ID |
| --- | --- | --- |
| P1 | 주간 보고 초안부터 작은 범위로 시작합시다. | PILOT |
| P2 | 출처와 기준일을 표시하고 담당자가 검토한 뒤 공유합시다. | REVIEW |
| P3 | 사용자 권한과 공유 범위를 확인한 자료만 사용합시다. | ACCESS |
| P4 | 준비시간과 수정량을 확인한 뒤 확대합시다. | MEASURE |
| P5 | 권한 검토 없이 모든 부서 자료를 바로 연결합시다. | OPEN_ALL |
| P6 | 아직 확인할 것이 많습니다. 검증 자료를 더 요청합시다. | 조건 없음, 요청 의견으로 기록 |

P5는 검토상 충돌을 드러내는 가상 대안이다. ACCESS와 OPEN_ALL은 동시 선택 불가. 충돌 시 ‘권한 확인 후 사용 / 권한 검토 없이 연결 중 어떤 의견을 전달할까요?’로 본인이 고르게 한다. P6만으로 참가자의 최종 표를 HOLD로 만들지 않는다.

조건 구성 화면에는 참가자가 확인한 모든 조건을 표시한다. 자유 입력에서 ‘검토 없이 공유’라고 써도 REVIEW 키워드가 있다고 자동 채택하지 않는다. 의미 해석 불명확 시 조건은 비워두고 선택적으로 확인받는다.

## 첫 반응 및 후속 질문

확인된 조건에 대응하는 관련 임원의 발언만 변화한다. 나머지 임원은 현재 우려를 유지한다.

| 조건 | 반응 예시 |
| --- | --- |
| PILOT | CFO·CAIO: “작게 시작하면 효과를 확인할 수 있겠습니다. 무엇을 측정할까요?” |
| REVIEW | CIO: “출처·기준일 표시와 공유 전 담당자 확인 절차를 수정안에 넣겠습니다.” |
| ACCESS | CISO: “권한과 공유 범위를 조건으로 넣겠습니다. 실제 검증은 착수 전에 필요합니다.” |
| MEASURE | CFO·CAIO: “준비시간과 수정량을 확대 판단의 기준으로 삼겠습니다.” |
| OPEN_ALL | CISO: “권한 검토 없이 연결하는 방식에는 우려가 남습니다.” |
| 조건 없음 | CEO: “말씀은 기록했습니다. 다른 확인 조건이 없다면 현재 안건으로 판단하겠습니다.” |

공통 후속 질문(v0.9: CIO 발화로 귀속, 근거 E1·E2. 화면에는 “CIO가 묻습니다”를 앞에 붙인다): “메일과 실적표의 숫자가 다르면 어떻게 처리할까요?” 화면은 빠른 답 3개를 기본으로 보여 주고 직접 입력은 접어 둔다(열면 300자 입력, 같은 조건 확인 과정).

- “출처·기준일 차이를 표시하고 담당자가 확인한 뒤 공유합시다.” → REVIEW 추가 제안.
- “최신 메일 값으로 바로 공유합시다.” → 기존 REVIEW가 있으면 충돌 확인 후 유지 또는 해제. 자동으로 덮어쓰지 않는다.
- “앞서 전달한 의견을 유지하겠습니다.” → 변경 없음.
- 직접 입력 → 같은 조건 확인 과정.

최종 안건 화면: 원안 텍스트와 선택한 조건을 함께 표시. 조건 하나 이상이면 수정안, 없으면 원안. REVIEW는 담당자 검토 **절차를 제안**한 것이지 이미 검토 완료라는 사실이 아니다. MOTION에서 조건 편집을 끝내고, 확인 후 VOTE 진입 시 motionId와 조건을 고정한다. 모든 표는 같은 motionId를 참조한다.

## 가상 임원 표결 규칙 — 우선순위대로 적용

결정적 규칙을 쓰며 LLM이 표를 정하지 않는다. 참가자의 최종 표는 임원 표의 입력이 아니다.

| 임원 | 위에서부터 처음 일치한 규칙 | 최종 표 |
| --- | --- | --- |
| CEO | OPEN_ALL 있음 | HOLD |
| CEO | 그 밖의 모든 경우 | YES |
| CFO·CAIO | OPEN_ALL 있음 | NO |
| CFO·CAIO | PILOT 및 MEASURE 있음 | YES |
| CFO·CAIO | 그 밖의 모든 경우 | HOLD |
| CIO | OPEN_ALL 있음 | NO |
| CIO | REVIEW 있음 | YES |
| CIO | REVIEW 없음 | NO |
| CISO | OPEN_ALL 있음 | NO |
| CISO | ACCESS 및 REVIEW 있음 | YES |
| CISO | ACCESS 있음 | HOLD |
| CISO | 나머지 | NO |

CISO는 정보 사용 조건과 검토 절차가 함께 포함되면 착수 전 실제 권한 검증을 전제로 찬성한다. 파일럿·측정 문구의 개수를 찬성 기준으로 삼지 않는다. 반응: “정보 사용 조건과 검토 절차를 갖춘 안건에 찬성합니다. 실행 전 권한 검증은 필요합니다.” 다른 임원도 운영·투자 우려를 유지할 수 있다.

## 결과와 AI 효율 체험

결과 순서: 결론 → 같은 크기의 5인 투표 카드 → 내 원문과 반영 조건 → 남은 확인 사항 → AI가 실제 도운 일.

- 가결: “수정안이 승인되었습니다. 실행 전에 확인할 조건도 함께 기록했습니다.”
- 보류: “추가 검토 후 다시 심의합니다. 이사님의 확인 요청을 기록했습니다.”
- 부결: “이번 안건은 부결되었습니다. 주요 우려와 이사님의 의견을 기록했습니다.”
- 의견 반영 예: REVIEW가 내가 확인한 조건이며 실제 최종 안건에 포함된 경우에만 “출처·기준일 확인과 담당자 검토 의견이 최종 안건에 반영되었습니다.”
- 남은 과제: 권한 검증, 검토 담당자 지정, 파일럿 성과 측정 등 실제 남은 항목만 표시.
- 정상 완주 결과에 항상 ‘자료 4장 자동 정리 데모 표시’를 포함한다. 추가 요약/비교/정리는 사용 기록이 있을 때만 표시하고 미사용이면 ‘추가 AI 도움은 사용하지 않았습니다.’ 실제 모델 호출 여부는 별도 구분한다.
- 효율 체감은 자료 4장 → 근거가 연결된 요약 → 내 발언에 적용의 과정을 통해 보여준다. 검증되지 않은 ‘업무시간 80% 절감’ 같은 수치는 금지.

개정 2026-09-09: CIO는 REVIEW가 없으면 NO. 조건 없음의 참가자 반대 경로와 원안 시간 만료 경로를 재계산했다. 자동 요약 표시·세션 운영은 [구현 지시서](../CLAUDE_IMPLEMENTATION.md)를 따른다.
