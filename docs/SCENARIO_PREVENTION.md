# 안건 ③ — 사고가 나기 전에 도울 수 있을까?

버전 1.0 · 2026-09-09 · P1 구현 기준. 모든 자료·대사·규칙은 체험용 가상 설정이며 실제 삼성화재 자료나 의결 규정이 아니다. 현장 리허설 후 조정할 수 있다.

## 브리핑

원안 `prevention-original`: 기상·시설 정보를 연결해 사업장 관리자에게 점검 항목을 알리는 AI 예방 서비스를 다수 사업장으로 확대한다. 알림 유용성·고객 수요·운영 부담·데이터 조건은 미검증이다.

의장: “사고가 나기 전에 고객을 도울 가능성을 어떻게 검증할까요?”

| ID | 자료 카드 | 가상 내용 |
| --- | --- | --- |
| E1 | 고객 의견 | 사업장 관리자는 흩어진 정보를 정리해 우선 점검할 항목을 알려주길 원한다. 지불 의향과 광범위한 수요는 확인되지 않았다. |
| E2 | 서비스 구상 | 기상·시설 정보를 바탕으로 점검 항목을 제안한다. 사고 예측 정확도나 사고 감소 효과는 입증되지 않았다. |
| E3 | 파일럿 여건 | 제한된 사업장에서 시험 가능하다. 데이터 갱신·알림 검토·중단 담당자는 미정이고 불필요한 알림 부담도 검증 전이다. |
| E4 | 데이터·투자 메모 | 정보 사용·접근·외부 공유 범위를 정해야 한다. 단계별 투자 기준과 고객 반응·알림 유용성 평가 계획은 미정이다. |

BRIEFING 자동 AI 정리 카드: “점검 우선순위를 정리해 달라는 고객 의견이 있습니다(E1). 서비스는 점검 보조 구상이며 사고 감소 효과는 미입증입니다(E2). 제한 파일럿에서 알림 검토·중단 운영(E3), 데이터 조건과 단계별 투자 기준(E4)을 확인해야 합니다.”

자료 4장 옆 상시 표시, ‘체험용 사전 구성’ 표기와 E1~E4 근거 연결을 제공한다. 클릭이나 실제 모델 연결은 필요하지 않다. 효과 수치·자료에 없는 사실은 생성하지 않는다.

## 초기 임원 의견

표 아이콘이나 찬반 선택 UI 없이 아래 검토 의견을 표시한다.

| 인물 | 발언 | 근거 |
| --- | --- | --- |
| CEO | 고객의 예방 활동을 돕는 가능성을 검토합시다. | E1, E2 |
| CFO · CAIO | 소수 사업장에서 유용성과 비용을 확인하고 단계적으로 투자합시다. | E3, E4 |
| CIO | 갱신·알림 검토와 중단 담당자를 정해야 운영할 수 있습니다. | E3 |
| CISO | 사업장 정보의 사용·공유 조건부터 확인해야 합니다. | E4 |

## 추천 문구와 구조화 조건

| 문구 ID | 문장 | 조건 ID |
| --- | --- | --- |
| P1 | 소수 사업장의 점검 보조 파일럿부터 시작합시다. | SMALL_PILOT |
| P2 | 알림 검토·데이터 갱신 담당자와 오류 시 중단 절차를 정합시다. | REVIEW_STOP |
| P3 | 사용·접근·외부 공유 조건을 확인한 사업장 정보만 활용합시다. | DATA_SCOPE |
| P4 | 고객 반응·알림 유용성·운영 부담을 확인한 뒤 단계적으로 투자합시다. | VALUE_GATE |
| P5 | 파일럿 검증을 생략하고 즉시 다수 사업장으로 확대합시다. | SCALE_NOW |
| P6 | 고객 수요와 불필요한 알림의 영향을 더 검증합시다. | 없음; 요청 의견으로 기록 |

ID는 scenarioId로 구분한다. P6의 검증 요청을 최종 HOLD 표로 추정하지 않는다. `SMALL_PILOT`와 `SCALE_NOW`는 동시 확정 불가다. 충돌하면 두 문구를 함께 보여주고 사용자가 유지할 조건을 고르게 한다. 취소 시 기존 입력을 보존한다. 다른 조건은 함께 제안 가능하나 아래 우선순위에 따라 즉시 확대/자동화 조건의 우려가 우선한다.

최종 제출 텍스트를 바탕으로 허용 조건을 제안하고 참가자가 확인한다. 부정문·상충 표현을 단순 키워드로 자동 채택하지 않는다. 이해하지 못한 입력도 원문으로 기록하고 조건 없이 진행할 수 있다. 후속 입력 시 누적 조건의 유지·해제를 확인한다. 조건 확정과 최종 투표는 별도다.

## 조건별 반응과 후속 질문

| 확인 조건 | 반응 |
| --- | --- |
| SMALL_PILOT | CFO·CAIO: “소수 사업장 파일럿 범위로 초기 투자를 제한하겠습니다.” |
| REVIEW_STOP | CIO: “담당자 검토·갱신·오류 시 중단 절차를 수정안에 넣겠습니다.” |
| DATA_SCOPE | CISO: “정보 사용·공유 조건을 기록하겠습니다. 착수 전 검증이 남습니다.” |
| VALUE_GATE | CFO·CAIO: “고객 반응·유용성·운영 부담을 다음 투자 판단 기준으로 삼겠습니다.” |
| SCALE_NOW | CFO·CAIO: “검증을 생략한 즉시 확대에는 반대합니다.” |
| 없음 | CEO: “확인 요청을 기록했습니다. 수정 조건이 없으면 원안으로 심의하겠습니다.” |

후속 질문(가정, 최대 1회): “시범 운영에서 불필요한 알림이 많다는 의견이 나온다고 가정하면 어떻게 하겠습니까?”

- “담당자가 알림을 검토하고 문제가 있는 기능은 중단한 뒤 재검증합시다.” → REVIEW_STOP 추가 제안. 충돌하는 기존 조건이 있으면 유지/해제를 본인이 확인한다.
- “파일럿 검증 없이 즉시 확대합시다.” → SCALE_NOW 추가 제안; SMALL_PILOT가 있으면 충돌 확인 후 하나만 확정한다.
- “앞선 의견을 유지하겠습니다.” → 조건 변경 없음.
- 직접 입력 → 동일한 원문 보존·허용 조건 확인 흐름.

최종 안건은 원안과 확인된 조건 전체를 표시한다. 조건 하나 이상이면 수정안이며, 조건 채택은 검증 완료를 뜻하지 않는다. MOTION에서 확인 후 VOTE 진입 시 motionId와 조건을 고정한다. 모든 의석은 같은 안건을 보고 투표한다.

## 가상 임원 표결 규칙

임원별 위에서 처음 일치하는 행 하나를 적용한다. 참가자 표나 LLM 출력은 규칙의 입력이 아니다.

| 임원 | 우선순위 조건 | 최종 표 |
| --- | --- | --- |
| CEO | SCALE_NOW 있음 | HOLD |
| CEO | 나머지 | YES |
| CFO·CAIO | SCALE_NOW 있음 | NO |
| CFO·CAIO | SMALL_PILOT 및 VALUE_GATE 있음 | YES |
| CFO·CAIO | 나머지 | HOLD |
| CIO | SCALE_NOW 있음 | NO |
| CIO | REVIEW_STOP 있음 | YES |
| CIO | REVIEW_STOP 없음 | NO |
| CISO | DATA_SCOPE 없음 | NO |
| CISO | DATA_SCOPE 있음 | HOLD |

CISO의 HOLD는 데이터 조건 제안 후에도 실제 검증이 남는다는 뜻이다. YES≥3 가결, NO≥3 부결, 나머지 보류. UNCAST는 별도 집계한다. 전체 의석은 5석이다.

임원 표 순서: CEO / CFO·CAIO / CIO / CISO. 각 행은 독립적인 체험이다.

| 확인 조건 | 임원 표 | 참가자 표 | 집계·결론 |

## 결과 기록과 검증

- 가결·보류·부결 모두 정상 엔딩이다. 내 원문·실제 채택 조건·소수 의견·최종 표를 기록한다. 채택되지 않은 조건이나 미확정 표를 채우지 않는다.
- 내 표의 영향은 임원 네 표와 안건을 고정한 상태에서 비교한다. 의견으로 조건이 달라진 영향과 한 표의 영향을 구분한다.
- 남은 과제 후보: 사업장 정보 권한 검증, 알림 검토·중단 담당자 지정, 고객 수요·알림 유용성·운영 부담 검증. 실제 남은 항목만 표시하며 절차가 채택돼도 이행 완료라고 쓰지 않는다.
- 자동 자료 정리 표시 이벤트가 있는 정상 완주 결과에 ‘자료 4장 자동 정리 데모 표시’를 항상 포함한다. 추가 도움 미사용은 별도로 표시한다. 실제 모델 호출과 사전 구성을 구분한다.
- 추가 AI 도움은 E1~E4를 근거로 의견 공통점, 원안/확인 조건 차이, 내 발언 정리만 제공한다. 사실·효과·표를 생성하지 않는다.
- 입력300자·편집 보존·충돌 확인·시간240초·무입력90초·세션 초기화·늦은 응답은 [구현 지시서](../CLAUDE_IMPLEMENTATION.md)를 따른다. 무입력 복귀는 결과 집계 없이 세션을 폐기한다.
- 대표 경로뿐 아니라 허용 조건 조합×참가자 YES/HOLD/NO/UNCAST를 검사한다. 각 임원 규칙의 총괄성, 5표 유지, 찬성·반대 양쪽 결정 경로, 결론 불변 경로를 검증한다.
