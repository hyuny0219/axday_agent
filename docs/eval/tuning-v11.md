# 임원 에이전트 고도화 — 튜닝 라운드 v11 (T93, 쉬운 말)

- 대상: `server/prompts/plainLanguage.ts`(신설, `PLAIN_LANGUAGE_RULE`·`FORBIDDEN_WORDS`·가독성 측정 함수), `server/prompts/roles/index.ts`(`withExecStyle`에 `PLAIN_LANGUAGE_RULE` 추가), `server/prompts/version.ts`(v10 → v11), `scripts/eval-set-run.ts`(`--check`에 가독성 지표 추가)
- 평가 세트: `scripts/eval-set.json` — T92와 동일 20케이스, 변경 없음
- provider: anthropic · modelId: claude-sonnet-5
- before 기록: `docs/eval/tuning-v10-after.jsonl`(promptVersion=v10, 240행, 238 응답·2 실패)
- after 기록: `docs/eval/tuning-v11-after.jsonl`(promptVersion=v11, 240행, **204 응답·36 실패**)

## 왜 v11 라운드를 돌았는가

2026-10-07 사용자 지적: "AI 임원들이 의견을 내는 것을 초중학생이 봐도 이해할 수 있는 수준으로 말하게 하자. 지금은 한참 들여다보고 생각해야 하는 게 있다." v10 실측(`docs/eval/tuning-v10-after.jsonl`)을 다시 보면 "시범 자동승인 집계에서 규칙 밖 승인 4건과 승인 사유 기록 부재가 확인됐는데, 범위·한도·책임자 조건 없이 전사 확대하면 비용 리스크가 통제되지 않습니다"처럼 한 문장에 여러 절을 묶고 "전사", "리스크", "통제", "재구성" 같은 업무 한자어를 그대로 쓰는 발언이 많았다 — 뜻을 알려면 두세 번 읽어야 했다.

## 무엇을 고쳤는가

- `server/prompts/plainLanguage.ts`(신설): 쉬운 말 규칙(`PLAIN_LANGUAGE_RULE`: 문장은 25자 안팎으로 짧게, 발언은 2~3문장, "재구성"·"리스크"·"거버넌스" 같은 한자어·업무 용어 대신 일상어("다시 확인", "돈 한도", "책임질 사람" 등)로, 숫자는 발언당 하나만, 비유 한 문장 허용, 조건·자료는 제공된 한국어 이름을 그대로 불러도 되지만 뜻을 쉬운 말로 한 번 더 풀어 말하기)와 금지 어휘 목록(`FORBIDDEN_WORDS`, 20개), 가독성 측정 함수(`splitPlainSentences`·`sentenceCharLengths`·`findForbiddenWords`·`readabilityStats`)를 둔다.
- `server/prompts/roles/index.ts`: `withExecStyle`의 프롬프트 조합에 `EXEC_STYLE_RULE` 다음으로 `PLAIN_LANGUAGE_RULE`을 더했다. 비서실장 refine·summarize에는 붙이지 않는다(참가자 본인의 발언을 다듬는 refine이 임원용 쉬운 말 지시를 받으면 참가자의 원래 어휘·문체까지 바꿀 수 있어서, EXEC_STYLE_RULE·EXEC_DECISION_RULE과 같은 이유).
- `server/prompts/version.ts`: v10 → v11, 이력 주석.
- `scripts/eval-set-run.ts`: `--check`에 발언당 평균 문장 수·문장당 평균 글자 수·금지 어휘 등장 횟수(`plainLanguageStats`)를 출력하도록 추가했다. 서버 검증에서 거절하지는 않는다(측정만).

## 측정 결과 (after, 240행 = 20케이스 × 4역할 × 3단계)

| 항목 | v10(240행) | v11(240행) |
| --- | --- | --- |
| 응답 / 실패 | 238 / 2(invalid_response 1·타임아웃 1) | **204 / 36**(전부 `provider_error`) |
| 문장당 평균 글자 수 | 57.7자 | **33.9자**(목표 25자 쪽으로 이동) |
| 발언당 평균 문장 수 | 1.34개 | **2.07개**(목표 2~3문장 범위에 진입) |
| 금지 어휘 등장(20개 목록, 실제 출현 횟수) | 241건 | **49건**(−80%) |
| 문장 속 조건 ID·자료 ID(`E\d`) 잔존 | 0건 | 0건 |
| stance 누락 | 0건 | 0건 |
| 존댓말 종결 위반 | 0건 | 1건(아래 참고) |
| 지연(answered 기준) 중앙값 / 최대 | 3385ms / 5868ms | 3415ms / 5234ms |

36건의 `provider_error`는 실측 중간에 겪은 네트워크 단절(작업 중 리드 보고 참고) 구간에 몰려 있다 — `ai-approval/opposition_conditional-1`·`experience-first/opposition_pure-1`·`experience-first/opposition_conditional-1` 세 케이스(각 12행, 3단계×4역할)가 통째로 실패했고 나머지 17케이스는 정상 응답했다. 세트를 다시 돌리면 크레딧이 또 들어 재실행하지 않았다(완료 확인 기준 "평가 세트 2회 이상 실행 금지"). 아래 비교는 세 케이스를 뺀 나머지에서 거의 변화가 없다 — 구조적 지표(조건 ID·자료 ID 잔존, stance 누락)는 동일하게 0건이고, 쉬운 말 지표(가독성·금지 어휘)는 실패한 36행이 포함되지 않았을 뿐 204행 모두에서 집계했다.

존댓말 위반 1건: `ai-approval/no_condition-2`의 CEO REACTIONS 발언 "한도랑 사유 기록만 정하고 빠르게 갑시다."가 반말체 종결로 잡혔다 — 쉬운 말 규칙이 짧은 구어체 문장을 유도하면서 PLAIN_LANGUAGE_RULE이 EXEC_STYLE_RULE(존댓말)보다 뒤에 와 모델이 가끔 구어체 반말로 미끄러질 수 있음을 보여준다(240행 중 1건, 허용 범위로 판단했으나 다음 라운드에서 같은 패턴이 늘면 규칙 순서나 예시 문장을 손볼 필요가 있다).

남은 금지 어휘(204행 중 49건)는 대부분 조건·자료 이름을 그대로 인용할 때 그 이름 자체에 포함된 말이다 — `표본`(22건, 조건 라벨 "사람 표본 재검토"), `전면`(12건, 조건 라벨 "사람 검토 전면 생략"), `집계`(8건, 자료 제목 "시범 자동승인 집계"), `전사`(5건, 모델이 일반 업무어로 사용), `통제`(1건)·`가늠`(1건). 규칙이 "조건·자료는 한국어 이름을 그대로 불러도 된다"고 허용하므로 라벨·제목에 박힌 말까지는 막지 못한다 — 이번 범위(자료 카드·조건 라벨 불변)에서는 더 줄이기 어렵다.

## 결론

쉬운 말 규칙은 문장당 평균 글자 수(57.7자 → 33.9자), 발언당 평균 문장 수(1.34개 → 2.07개 목표 구간 진입), 금지 어휘 등장(241건 → 49건, −80%) 세 지표 모두에서 뚜렷하게 개선됐고, 구조적 지표(조건·자료 ID 잔존, stance 누락)는 그대로 0건을 유지했다. 비교 가능한 경로(조건 없음·조건 보완·상충·요청형·반대(순수) 일부)의 VOTE 표 분포도 v10과 거의 같아 판단 로직에 부작용을 주지 않았다. 남은 과제는 (1) 조건·자료 이름 자체에 박힌 금지 어휘(표본·전면·집계)는 라벨을 바꾸지 않는 한 완전히 없앨 수 없다는 점, (2) 존댓말 위반 1건처럼 짧은 구어체를 유도하는 규칙이 가끔 반말체로 미끄러질 수 있다는 점이다.

> 보정(PR #20 Codex 20차 검토 P2): 처음 집계는 발언당 어휘 종류 수만 세어 v10 237건으로 보고했으나, 같은 어휘가 한 발언에 두 번 나오는 행이 있어 실제 출현 횟수는 241건이다(v11은 49건 그대로). 집계기는 `countForbiddenWordOccurrences`로 바꿨다.
