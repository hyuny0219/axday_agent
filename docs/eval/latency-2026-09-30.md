# 라운드 지연 분포 — T65 (2026-09-29 시연 지연 진단)

- 목적: `server/config.ts`의 `ROUND_TIMEOUT_MS`(기본 8000, OPINIONS·VOTE·probe)·`REACTION_TIMEOUT_MS`
  (기본 12000, REACTIONS·FOLLOWUP)의 기본값 근거를 실측으로 남긴다.
- 출처: **새로 실행하지 않았다.** `docs/eval/tuning-v7-after3.jsonl`(144행, provider=anthropic,
  modelId=claude-sonnet-5, promptVersion=v7, 2026-09-29 T63 마지막 실측)의 각 행에 이미 실려
  있는 `stage`·`roleId`·`latencyMs`만 다시 집계했다(`node`로 한 줄 스크립트, 저장소에 남기지
  않음). 이 파일은 12케이스 × 4역할 × 3단계(OPINIONS·REACTIONS·VOTE) = 144행이며, 전량
  `status:'answered'`다(실패 0건).
- **VOTE 행에 대한 주의:** `handleVote`(`server/handlers/vote.ts`)는 이 실측 시점에 자체
  `latencyMs`를 응답에 싣지 않았다(T65에서 이번에 추가했다). `docs/eval/tuning-v7-after3.jsonl`의
  VOTE 행 `latencyMs`는 평가 스크립트(`scripts/eval-set-run.ts`)가 `handleVote` 밖에서
  `provider.complete()` 호출을 별도로 계측해 채운 값이다(README "PR #10 Codex 18차 검토 P2"
  참고) — 서버가 로그로 남기는 값과 소스가 다르다는 뜻이며, 실제 왕복 지연이라는 점은
  같다.
- FOLLOWUP은 이 평가 세트에 케이스가 없어(고정 12케이스가 OPINIONS·REACTIONS·VOTE 경로만
  구성) 실측 행이 없다. REACTIONS 값을 그대로 참고 근거로 쓴다 — FOLLOWUP은 REACTIONS와 같은
  프롬프트 구조(참가자 발언·이전 발언을 함께 싣는다)이므로 REACTIONS의 지연 분포가 가장
  가까운 대체 표본이다.

| stage | p50 | p95 | max | 상한(기본값) | p95가 상한 안에 드는가 |

| OPINIONS | 4108 | 4781 | 4859 | ROUND_TIMEOUT_MS 8000 | 예 (여유 3219ms) |
| REACTIONS | 4258 | 4695 | 4999 | REACTION_TIMEOUT_MS 12000 | 예 (여유 7305ms) |

## 8000 vs 12000 — 실측만으로는 REACTIONS가 더 오래 걸린다는 근거가 약하다

이 표만 보면 REACTIONS(p95 4695ms)가 OPINIONS(p95 4781ms)보다 오히려 살짝 빠르다 — 고정
평가 세트(12케이스)는 회의 기록이 짧아 REACTIONS의 "참가자 발언·동료 발언을 더 실어 프롬프트가
길다"는 특성을 충분히 반영하지 못한다. `REACTION_TIMEOUT_MS`를 8000이 아니라 12000으로 둔
근거는 이 표의 실측이 아니라 **2026-09-29 실제 부사장 시연에서 REACTIONS 단계 응답이 지연·
확인 필요로 끝난 사고 보고**(`docs/TASKS.md` T65 목표)다 — 실제 체험은 라운드가 진행될수록
회의록에 발언이 누적돼 프롬프트가 이 평가 세트보다 길어지고, 네트워크·서버 부하도 평가
스크립트 환경과 다르다. 따라서 12000은 "실측 p95 + 안전 여유"가 아니라 "관측된 장애를 다시
겪지 않기 위한 보수적 상한"이며, 다음 실측(REACTIONS 단계가 여러 차례 누적된 실제 세션
로그, `logs/board-*.jsonl`)이 쌓이면 값을 다시 조정한다.

## 재현 방법

```
node -e "
const fs = require('fs');
const rows = fs.readFileSync('docs/eval/tuning-v7-after3.jsonl', 'utf-8')
  .trim().split('\n').map((l) => JSON.parse(l));
const byStage = {};
for (const r of rows) (byStage[r.stage] ??= []).push(r.latencyMs);
for (const [stage, vals] of Object.entries(byStage)) {
  const sorted = [...vals].sort((a, b) => a - b);
  const pct = (p) => sorted[Math.min(sorted.length - 1, Math.floor(sorted.length * p))];
  console.log(stage, sorted.length, 'p50=' + pct(0.5), 'p95=' + pct(0.95), 'max=' + sorted[sorted.length - 1]);
}
"
```
