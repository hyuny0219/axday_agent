# 임원 에이전트 고도화 — 튜닝 라운드 v5 (T54, 인용을 자료명으로 교체)

- 대상: `server/prompts/common.ts`(가드레일 인용 지시, `formatEvidence` 자료 목록 순서), `server/prompts/version.ts`(v4 → v5)
- 평가 세트: `scripts/eval-set.json`(12케이스) · 실행기 `scripts/eval-set-run.ts`
- provider: anthropic · modelId: claude-sonnet-5
- before 기록: `docs/eval/tuning-v5-before.jsonl`(promptVersion=v4, 144행) — T52(참가자 화면에서 E1~E4 표기 제거)가 이미 반영된 상태에서 v4 프롬프트로 다시 측정한 기준선. 이전에 커밋됐던 같은 이름의 파일은 provider_error로 84/144행이 실패해 이번에 다시 실행해 덮어썼다(원인은 이 라운드의 변경과 무관 — 재실행 시 0건 실패로 재현됨).
- after 기록: `docs/eval/tuning-v5-after.jsonl`(promptVersion=v5, 144행)

## 왜 v5 라운드를 돌았는가

T52가 참가자 화면에서 `E1`~`E4` 카드 ID 표기를 없앴는데도, 공통 가드레일은 여전히 "모든 주장에는 제공된 근거 카드 ID(예: E1)를 인용하십시오"라고 지시해 임원 발언 문장에 "…미정입니다(E4)"처럼 화면에 없는 기호가 그대로 나왔다.

## 무엇을 고쳤는가

- `buildCommonGuardrails()`의 인용 지시를 "자료 이름을 문장 속에서 그대로 인용하고, 자료 ID(E1 등)는 evidenceIds 필드에만 넣으라"로 바꿨다. 응답 스키마의 `evidenceIds`(`server/validate.ts`)는 그대로 두어 ID로만 채우게 한다 — 검증·기록용 필드는 건드리지 않는다.
- `formatEvidence()`가 자료 목록을 보여줄 때 `자료명 [ID: E1]` 순서로 바꿔, 모델이 문장에는 이름을, 스키마 필드에는 ID를 쓰도록 순서로도 유도했다.
- `PROMPT_VERSION`을 v4 → v5로 올렸다.
- `scripts/eval-set-run.ts`에 `findEvidenceIdMentions()`를 추가해 `message`·`reason` 필드에 `E\d` 패턴이 남는지 코드로 집계한다(`--check`가 기존 존댓말 위반 집계와 함께 이 수치도 찍는다).

## CAIO "연계·운영" 저하 — 사전 정의 지표에서의 후퇴로 기록한다

> **정정(PR #11 Codex·Astra 검토 반영, 2026-09-28):** 처음 작성한 판정은 결과를 본 뒤 여덟 단어 중 하나만 있으면 통과하는 넓은 지표를 추가해 "판단 기준 후퇴 아님"으로 결론지었다. 사후에 만든 지표는 사전 정의 지표의 저하를 뒤집는 근거가 될 수 없으므로 철회한다.

- **관측:** tuning-v2·v3에서 쓴 사전 정의 지표 "연계·운영" 포함 비율이 24/36 → 14/36으로 줄었고, 같은 v5 프롬프트의 독립 재실행에서도 17/36으로 재현됐다. CAIO 역할 프롬프트(`server/prompts/roles/caio.ts`)는 바뀌지 않았으므로 원인은 이번 라운드의 공통 가드레일·인용 방식 변경에 있다.
- **원인 가설(미확인):** 자료 인용이 `E4`(2자)에서 자료명(4~6자)으로 길어져 부연에 쓸 문장 예산이 줄었을 가능성. 다만 실측 최대 길이는 message 90/120자, reason 106/160자로 한도에 닿지 않아 이 가설은 데이터로 입증되지 않는다. 가설로만 남긴다.
- **넓은 어휘 지표(36/36 유지)는 참고값이다.** 여덟 단어 중 하나만 있으면 통과하는 지표는 판단 기준이 보존됐음을 입증하지 못한다.
- **처리:** 완료 기준 네 항목 중 "역할 키워드 악화 없음"은 CAIO에서 **미충족**으로 기록한다. 판단 기준 보존 여부는 사후 지표가 아니라 **사전에 정의한 역할별 평가 기준**(예: CAIO 응답이 기술 구현 가능성·데이터 준비·체계 연계·운영 부담 중 무엇을 근거로 삼았는지 사람이 12케이스를 읽어 표로 남김)으로 전후를 같은 잣대로 비교해야 한다. 이 비교는 다음 프롬프트 변경(T59, `PROMPT_VERSION` v6)의 전후 측정에 사전 정의 항목으로 넣어 함께 확인한다.

## "자료 밖 사실" 자동 판정의 한계 — 수동 재점검

> PR #11 Astra 검토가 after.jsonl 61행(CEO, "시범 게시판 집계에서 참여율 증가가 보이나")을 반례로 들었다. E2는 실명 320건·익명 시범 140건을 "집계 기간과 참여 범위가 달라 직접 비교할 수 없다"고 적었으므로 "참여율 증가"는 자료가 뒷받침하지 않는 추론이다.

- 자동 판정 (1)은 evidenceIds 밖 자료 인용과 자료에 없는 수치를 잡지만, **자료의 결론을 넘어서는 추론**은 잡지 못한다.
- 수동 재점검(message·reason에서 "참여 증가·참여율 증가·참여가 늘었" 류 단정): before 5건(CEO 37·41·121·129·133행), after 3건(CEO 1·25·61행). 같은 부류의 추론이 v4에도 있었으므로 이번 라운드의 후퇴는 아니지만, "자료 밖 사실 0건"이라는 표현은 자동 판정 기준에 한정한 것이었다. 아래 판정에서 그렇게 고쳐 적는다. CFO의 "공수 증가 우려"는 자료 E3(담당자 부재)에서 나온 우려 표현이라 반례로 세지 않았다.
- 이 추론 부류를 막는 지시("자료가 비교 불가라고 적은 수치로 증감을 단정하지 말 것")는 T59 프롬프트 변경에 포함하고, 위 수동 재점검을 같은 방식으로 반복해 전후를 비교한다.

## 라운드 판정

완료 기준 네 항목 중 **세 항목 충족, 한 항목 미충족.**

- 충족: 발언 문장에 `E\d` 패턴이 남지 않음(142건 → 0건, 이번 라운드의 목표). 근거 미인용 0건 유지. 자료 밖 사실 — **자동 판정 기준으로** 0건 유지(자료 결론을 넘는 추론은 before 5·after 3건으로 후퇴 아님, 위 절). 지연·문장 길이 악화 없음(오히려 개선). 검증 실패·8초 초과·무조건 찬성·반대 역할 없음도 유지.
- 미충족: 역할 키워드 악화 없음 — CAIO 사전 정의 지표 24/36 → 14/36. 사후 넓은 지표로 뒤집지 않는다. 판단 기준 보존 여부는 T59의 사전 정의 역할 평가로 확인한다.

카드의 크기(S)에 맞춰 이 라운드는 여기서 마치고, CAIO 지표 회복과 추론 부류 지시는 T59(`PROMPT_VERSION` v6)로 넘긴다.
