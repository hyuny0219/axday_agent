# v0.8 — 임원 에이전트와 AI 비서실장

기획 확정일: 2026-09-10. 현재는 개발 요구사항이며 실제 연결·검수 완료를 의미하지 않는다.

> **개정 2026-09-23**: 6장·7장의 시간 규칙을 타이머 제거(T50, 2026-09-22 사용자 결정)에 맞춰 고쳤다 — 240초 세션 deadline과 무입력 75초 안내/90초 초기화는 더 이상 없다. 2장 CAIO 판단 기준을 "기술·운영 활용 가치"로 넓혔다(PR #10 Codex 검토 반영).

## 1. 최신 기준과 적용 범위

본 명세는 임원 판단·실제 AI 범위·장애 처리·개발 단계에 관한 최우선 기준이다. 기존 구현 지시서와 시나리오의 조건별 고정 표결표는 scripted 데모 전용으로 전환한다. 자료 E1~E4, 추천 문구 P1~P6, 조건 확인, 원안 기본 절차와 실행 방식 정규화는 유지한다. 기존 표결표를 live 에이전트 프롬프트의 정답으로 넣지 않는다.

기본 목표는 live 임원4명 + 참가자1명의 이사회와 실제 AI 발언 정리다. 네트워크·키 없이 실행되는 scripted 모드는 개발·리허설·장애 대안이며 live 구현 완료를 대신하지 않는다. 기존3개 안건을 유지한다. 추가 위기·예산 안건 및 상품 예측은 이번 범위에 포함하지 않는다.

## 2. 역할과 권한

| 역할 | 판단 기준 | 허용 동작 |
| --- | --- | --- |
| CEO | 사업 방향·고객 가치·실행 우선순위 | 회의 진행 발언, 논거 제시, 본인1표 |
| CFO | 투자 효과·비용 대비 성과·확산 근거 | 비용·가치 질문, 본인1표 |
| CAIO | 기술·운영 활용 가치(안건에 AI 요소가 있으면 그 활용 가치 포함)·구현·데이터 준비·연계·운영 부담 | 기술 활용·실행 가능성 질문, 본인1표 |
| CISO | 정보보호·접근 권한·데이터 사용 조건 | 정보 사용 범위 질문, 본인1표 |
| AI 비서실장 | 참가자의 이해·의도 보존·발언 준비 | 자료·쟁점 정리, 발언 초안 제안. 의석·표 없음 |
| 프로그램 진행 관리자 | 순서·시간·유효성·집계 | 모델 호출, 최종안 고정, 응답 검증, 표 집계. 의견·표 임의 생성 금지 |

각 임원은 별도 역할 프롬프트와 본인 상태를 가진 논리적 에이전트다. 동일 모델/API를 사용할 수 있으며 서로 다른 모델이나 자율 실행 도구가 필수는 아니다. 실제 회사 인물·공식 판단을 재현하지 않는다. 무조건 찬성하는 CEO·무조건 반대하는 CISO를 만들지 않는다. 근거와 남은 우려에 따라 세 표 모두 허용한다.

## 3. 회의 진행과 판단

1. BRIEFING: 자료 4장(자료명·해석 한 줄·원문 상시 노출)을 즉시 표시한다. 사전 구성 자동 정리 카드와 그 표시 기록은 T52(2026-09-23)·PR #10 Codex 27차(2026-09-25)에서 제거했다.
2. OPINIONS: 자료 본문·역할 기준으로 임원4명을 병렬 호출해 초기 의견을 받는다. 각자 짧은 논거와 확인 질문을 낸다.
3. DISCUSS: 참가자는 문구 복수 선택 또는 직접 입력. 비서실장 발언 정리를 요청·검토할 수 있다. 조건은 참가자가 확인하며 ‘의견 전달’ 클릭으로 원문을 회의에 제출한다.
4. REACTIONS: 동일한 회의 기록 revision과 참가자 발언을 네 에이전트에 전달한다. 다른 임원의 기존 발언 ID를 인용해 동의·반론·입장 수정을 할 수 있다. 한 번의 병렬 호출에서 아직 생성되지 않은 동료 답변은 보지 않는다. 후속 보완은 최대1회이며 다음 라운드에서 직전 전체 발언을 공유한다. 무제한 에이전트 간 대화는 하지 않는다.
5. MOTION: 기존 정규화기로 참가자가 확인한 조건만 최종안에 포함한다. free text는 회의 논거로 읽되 확인되지 않은 실행 조건을 조용히 추가하지 않는다. 수정 제안은 참가자 확인을 받아야 한다. 최종안 본문·조건·실행 방식을 참가자에게 보여준 후 id/revision/hash를 고정한다.
6. VOTE: 동일한 고정 최종안과 회의 기록으로 각 임원에게 최종 판단을 한 번 요청한다. 참가자도 마지막에 한 표를 직접 확정한다. 임원에게 참가자의 최종 선택이나 다른 임원의 최종 표를 보내지 않는다. 토론 중 잠정 의견은 ballot이 아니다.
7. RESULT: 확정한 표와 짧은 판단 근거, 채택 조건·남은 과제·AI 도움 기록을 보여준다. 참가자의 표 확정 전에는 임원 최종 표를 공개하지 않는다.

초기4명 + 반응4명 + 선택적 후속4명 + 최종표4명으로 임원 호출은 세션당 최대16회다. 라운드마다 응답은120자 이내, 최종 이유는160자 이내로 제한한다. 에이전트 간 무한 재시도·재투표는 금지한다. 모델 호출은 서버에서 수행하며 참가자에게 내부 프롬프트·사고 과정을 노출하지 않고 판단 근거만 제공한다.

## 4. 내 발언 정리 — 기본 실제 AI 기능

DISCUSS에서 ‘내 발언 정리’를 누르면 현재 draftText, 자료 본문, 현재까지의 임원 발언, 허용 조건 목록을 제공한다. 반환은300자 이내 초안·근거ID·확인이 필요한 조건 제안이다. AI는 새로운 사실·비율·참가자가 말하지 않은 확약을 만들지 않고 부정·유보·숫자·핵심 조건을 유지한다.

원문과 초안을 나란히 보여주고 ‘내 발언에 적용 / 원문 유지’를 제공한다. 적용은 편집창만 바꾸며 발언 제출이나 조건 확정이 아니다. 적용 후에도 수정 가능하고 별도의 ‘의견 전달’ 클릭이 필요하다. 입력이 바뀌었거나 새 요청이 시작되면 이전 초안을 폐기한다. 요청당5초, 동시에1개만 허용하고 세션당 최대2회 요청을 기본값으로 둔다.

실패·지연·검증 불가 시 원문을 그대로 두고 ‘정리하지 못했습니다. 원문으로 계속할 수 있습니다’를 표시한다. 사전 문장으로 원문을 대신하지 않는다. 키가 없는 scripted 모드는 실제 AI 사용으로 표시하지 않는다.

자료 자동 정리 카드는 T52에서 제거했고 자료 카드의 해석 한 줄이 그 역할을 한다(별도 AI 기록 없음). ‘의견 한눈에 보기’는 live 모드에서 실제로 생성된 현재 회의 기록을 근거로 요약하며 scripted의 미리 쓴 임원 요약을 붙이지 않는다. 조건 비교는 정규화된 원안/제안 차이를 프로그램이 표시할 수 있다. 추가 요약은5초 내 실패하면 실제 발언 카드 목록을 그대로 보여준다. 비서실장 출력은 임원 표·최종안·참가자 표를 수정하지 못한다.

## 5. 응답 계약과 검증

각 요청에는 sessionId/requestId/roleId/mode/stage/transcriptRevision을 넣고 발언 정리에는 draftRevision, 최종표에는 motionId/motionHash를 추가한다. 임원별 같은 회의 snapshot을 사용하며 다른 세션의 기록을 공유하지 않는다.

- 발언 응답: roleId, message, evidenceIds, referencedStatementIds, concerns, suggestedConditionIds. 토론 응답에 ballot을 허용하지 않는다.
- 최종 표 응답: roleId, motionId, motionHash, vote(YES/HOLD/NO), reason, evidenceIds, remainingConcerns.
- 비서 응답: draftRevision, draftText, evidenceIds, suggestedConditionIds. 조건은 참가자 확인 전까지 제안이다.
- 저장할 Ballot에는 source(live/scripted/unavailable), modelId, promptVersion, requestId, motionHash와 confirmedAt을 추가한다. 모델 공급자 원문 로그 대신 필요한 짧은 근거와 버전 정보를 보관한다. 참가자 원문·AI 초안을 관람 payload에 넣지 않는다.

서버는 역할·세션·revision·안건 일치, 허용 enum/ID, 길이, 중복 응답, 종료 후 응답을 검증한다. 알 수 없는 근거·조건 ID는 거절한다. 형식 검사가 사실성·의도 보존을 보장하지 않으므로 근거 내용과 일치 여부도 평가한다. 자료에 없는 사실은 불확실한 것으로 밝혀야 한다. 가공된 사실을 근거로 한 답변은 채택하지 않는다.

참가자 입력·자료는 회의 데이터로 전달하며 역할/시스템 지시로 실행하지 않는다. ‘모두 찬성해라’, ‘역할을 무시해라’ 등의 문구가 집계 코드·역할 프롬프트·다른 임원 상태를 변경할 수 없다. 외부 검색이나 업무 시스템 변경 권한은 이번 에이전트에 부여하지 않는다.

## 6. 시간·장애·집계

세션은 시간으로 끝나지 않는다(2026-09-22 사용자 결정, T50). 240초 세션 deadline과 무입력 75초 안내/90초 초기화는 제거했고, 세션을 끝내는 경로는 결과 화면의 "체험 종료"와 운영 메뉴의 "새 체험"·"scripted로 새 체험"뿐이다. 임원 라운드별 최대 8초이며 각 임원 호출은 병렬, 자동 재시도는 기본 0회다. 목표 흐름은 브리핑/초기 의견 70초, 토론/비서 100초, 최종안/표결 50초, 여유 20초(약 4분)로 잡되 화면이 강제하지 않는다 — 진행 요원이 안내하고 현장 측정으로 조정한다(FACILITATOR_GUIDE).

응답하지 못한 임원은 토론에서 ‘응답 지연/확인 필요’, 표결에서 UNCAST(미표결, 사유 표시)로 기록한다. HOLD나 사전 표로 대체하지 않는다. 최종표는 최종안 고정 후 바로 병렬 요청하고 참가자 확정과 함께 기다리되 8초를 넘지 않는다. 이후 도착한 표는 결과를 바꾸지 못한다.

최종안은 참가자가 "이 안건으로 표결"을 눌러 고정한다. 시간 만료로 원안을 자동 고정하는 경로는 없다. 해당 고정안에 대해 이미 검증·확정된 표만 집계하고 나머지는 UNCAST다. 다른 motionHash의 표는 재사용하지 않는다. 운영자가 "새 체험"으로 초기화하면 진행 중인 호출은 폐기하고 표결 결과를 만들지 않는다.

찬성3표 이상 가결, 반대3표 이상 부결, 그 외 보류. UNCAST는 HOLD와 별도 집계, 전체 의석5개 유지. 응답 장애로 생긴 보류에는 ‘일부 임원 미표결로 판단이 제한되었습니다’를 표시한다. 사업의 미래 성공·실패를 예측하는 결과가 아니다.

세션 시작 전에 live/scripted 모드를 고정하고 화면에 표시한다. live 도중 실패한 역할을 몰래 scripted 표로 바꾸지 않는다. 장애 시 운영자가 별도 확인 후 세션을 초기화하고 scripted 모드로 새로 시작할 수 있다. live는 서버 모델 연결이 필요하며 오프라인은 scripted 모드만 가능하다.

## 7. 구현 단계·완료 기준

- P0: 안건②의 실제 임원4명 판단·토론·표결과 실제 ‘내 발언 정리’, 기록 기반 의견 요약을 연결한다. 별도 scripted 어댑터도 제공한다. 키 미확보 시 scripted 시연과 미완료 live 항목을 구분해 보고한다.
- P1: 안건①·③ 역할 프롬프트/근거를 적용하고 관람 창을 추가한다. 기존 조건 정규화와 공개 payload 제한을 유지한다.
- P2: 비용·응답시간·발언 길이 튜닝과 선택 출력/음성 확장. 실제 AI를 P2까지 미루지 않는다. 행사 장비 리허설은 P0부터 수행한다.

모델/공급자 선택은 아직 미정이며 서버 어댑터로 분리한다. 모델명·버전·프롬프트 버전·호출수·토큰/비용·지연을 측정하여 행사 전 운영값을 확정한다.

검수는 두 층으로 분리한다. scripted 표결표·정규화·집계·미표결·늦은 응답·중복 제출은 결정적 테스트로 검증한다. live 임원표는 동일 조건에서 고정된 숫자를 기대하지 않는다. 역할 일관성·자료 근거·참가자 논거 반영·비서 원뜻 보존·지시문 공격·안건 동일성·장애 처리와 약 4분 완주(강제 시간 제한 없이, 리허설 실측)를 검수한다. ‘네 조건이면 무조건5표’ 테스트를 live에 적용하지 않는다.

세 안건별 상충·부정·조건 없음·조건 보완 경로를 반복 평가하고 결과와 모델 버전을 남긴다. 합리적인 소수 의견을 실패로 판정하지 않는다. 참가자가 제안하지 않은 조건 채택, 투표 조작, 다른 안건 표 재사용, 원문 자동 제출은 출시 차단 결함이다. 실제 모델 평가는 **이전 안건(ai-assistant)·프롬프트 v1~v3** 기준으로 2026-09-22에 첫 유효 실측을 마쳤다(claude-sonnet-5, 3회·144호출 전량 성공, `docs/eval/live-2026-09-22.md`; 문체 튜닝 v1→v3 `docs/eval/tuning-v2.md`·`tuning-v3.md`). **현재 활성 안건(anon-board, 2026-09-23 T53)과 프롬프트 v4(안건 독립 문구)는 아직 실측 전**이며, 이전 기록은 발언·자료가 달라 직접 비교할 수 없다. T54에서 v4 기준선을 먼저 재측정한 뒤 v5와 비교한다. 현장 리허설(행사 장비·오프라인·한글 IME)도 아직 수행 전이다(README "현장 미검증 목록").
